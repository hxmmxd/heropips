Stops & Auto-Close

Trailing Stop & Auto-Close Mechanics

Scalping targets are narrow. We rely on three distinct automated stop management mechanics to lock in profits and protect accounts.

Distance-Based Trailing
Stop Loss stays a fixed distance behind the highest bid/ask price achieved during the trade. As price trends upward, SL follows.
Threshold-Based Step Stops
SL shifts to pre-configured points only when designated profit milestones are breached. Standard configurations move to tight lock-in states.
• Profit 50 pts → SL Entry + 20 pts
• Profit 100 pts → SL Entry + 60 pts
• Dynamic locking server-side
Breakeven Auto-Shift
When the trade reaches 50% of the target Take Profit value, the Stop Loss is immediately adjusted to the exact Entry Price (0 loss).
• Entry Price: 2340.00
• Target Profit: 2346.00 (60 pts)
• At 2343.00 → SL shifts to 2340.00
• Risk reduced to exactly 0.00

Limitations & Risks

Execution Limitations & Risk Gaps

Addressing technical limits and broker constraints with automated defensive risk controls.

Broker Scalp Bans
High Risk
Some brokers ban trades held <60s.
Mitigation: Pre-verify broker specification settings. Restrict execution if stopsLevel > 20.
Serverless WS Timeout
Technical
Vercel Serverless functions timeout at 60s, breaking sockets.
Mitigation: Run the WebSocket listener on a dedicated Utho VPS. Relay ticks via SSE.
Spread Widening
Medium
Spreads balloon during NY market news releases or overnight rollovers.
Mitigation: Query `/symbols/specification` before trade. Block orders if spread > 2x normal.
Slippage & Latency
Medium
REST order placement takes 1-2s. Slippage fills orders at worse prices.
Mitigation: Use `ORDER_FILLING_IOC` mode. Reject execution when slippage threshold is breached.
Daily Drawdown Guard
New Feature
Scalpers can hit losing streaks rapidly.
Mitigation: Build a 3% daily loss circuit breaker. Auto-close all open trades on trigger.
Position Count Limit
New Feature
Grid scalping can over-leverage accounts.
Mitigation: Enforce strict limit checks in `scalpingRisk.ts` allowing maximum 2 open positions.

02 WebSocket Connection & Relay Event Handlers

MetaAPI's raw quote streaming relies on socket.io. Since Vercel serverless functions restrict open WebSocket loops, we decouple streaming by running a dedicated Node process on our **Utho VPS** in London. This process listens to ticks and relays events to the frontend UI via Server-Sent Events (SSE). 

import MetaApi from 'metaapi.cloud-sdk/node';

const api = new MetaApi(process.env.META_API_TOKEN);

async function connectStreaming(accountId: string) {
  const account = await api.metatraderAccountApi.getAccount(accountId);
  const connection = account.getStreamingConnection();
  
  connection.addSynchronizationListener({
    onSymbolPriceUpdated(instanceIndex, price) {
      // Streamed on every tick change. ~1ms latency
      console.log(`[TICK] ${price.symbol}: Bid ${price.bid} / Ask ${price.ask}`);
      // Send message to local SSE relay queue
    },
    onPositionUpdated(instanceIndex, position) {
      console.log(`[P&L UPDATE] Position ${position.id}: P&L ${position.profit}`);
    },
    onPositionRemoved(instanceIndex, positionId) {
      console.log(`[CLOSED] Position ${positionId} terminated`);
    }
  });

  await connection.connect();
  await connection.waitSynchronized();
  
  // Subscribe to raw streaming ticks and minute candles
  await connection.subscribeToMarketData('XAUUSD', [
    { type: 'quotes' },
    { type: 'candles', timeframe: '1m' },
    { type: 'ticks' }
  ]);
  
  return connection;
}
Event Name Trigger Boundary Scalping Logic Application
onSymbolPriceUpdated Every raw tick bid/ask change Refreshes spread values and paints local chart ticks.
onCandlesUpdated Every candle close/high/low shift Recomputes indicators (VWAP, EMA) on 1-minute chart.
onPositionUpdated Any P&L change on broker side Fires Breakeven gate if profit reaches 50% target threshold.
onPositionRemoved Position is deleted on server Cleans terminal UI slots and triggers the 90s safety cooldown timer.
onBrokerConnectionStatusChanged Node loses connection to broker Fires warning alerts to Terminal UI and pauses active trade generation.

async function checkSpreadOk(
  accountId: string, 
  symbol: string, 
  maxSpreadPoints: number
): Promise<{ ok: boolean; spread: number; detail: string }> {
  // Fetch bid/ask quotes
  const tick = await fetchCurrentTick(accountId, symbol);
  // Fetch symbol specifications (digits, tick size)
  const spec = await fetchSymbolSpec(accountId, symbol);
  
  // Calculate spread in points
  const spread = (tick.ask - tick.bid) / spec.tickSize;
  
  if (spread > maxSpreadPoints) {
    return {
      ok: false,
      spread,
      detail: `Spread ${spread} pts exceeds threshold (${maxSpreadPoints} pts). Entry blocked.`
    };
  }
  return {
    ok: true,
    spread,
    detail: `Spread ${spread} pts is acceptable for scalping.`
  };
}
async function moveToBreakeven(
  accountId: string, 
  positionId: string, 
  entryPrice: number
) {
  // Send modification payload to broker
  return await restTrade(accountId, {
    actionType: 'POSITION_MODIFY',
    positionId: positionId,
    stopLoss: entryPrice, // SL set exactly to open entry price
    stopLossUnits: 'ABSOLUTE_PRICE'
  });
}
async function isBrokerScalpFriendly(
  accountId: string, 
  symbol: string
): Promise<{ compatible: boolean; issues: string[] }> {
  const issues: string[] = [];
  const spec = await fetchSymbolSpec(accountId, symbol);
  
  // 1. Verify stops level
  if (spec.stopsLevel > 20) {
    issues.push(`High stops level (${spec.stopsLevel} points). tight stops restricted.`);
  }
  
  // 2. Verify trade execution capabilities
  if (spec.tradeMode !== 'SYMBOL_TRADE_MODE_FULL') {
    issues.push(`Trade mode is ${spec.tradeMode}. Instant market orders may fail.`);
  }
  
  // 3. Verify current spread levels
  const tick = await fetchCurrentTick(accountId, symbol);
  const spread = (tick.ask - tick.bid) / spec.tickSize;
  if (spread > 30) {
    issues.push(`Spread too wide (${spread} points) for scalping targets.`);
  }
  
  return {
    compatible: issues.length === 0,
    issues
  };
}

04 Database Schema Extensions & Configurations

Executing high-frequency scalping strategies requires expanding existing database tables. We need to track the trade type (swing vs. scalp), track daily realized P&L to feed the circuit breaker, and audit lot sizes to confirm rebate eligibility.

Supabase PostgreSQL Schema Upgrade

-- 1. Track trade mode tag
ALTER TABLE public.trades 
ADD COLUMN IF NOT EXISTS trade_type varchar DEFAULT 'swing';

-- 2. Daily tracking table for circuit breaker
CREATE TABLE IF NOT EXISTS public.daily_pnl (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid REFERENCES profiles(id),
  trade_date date NOT NULL,
  realized_pnl numeric(15,2) DEFAULT 0,
  trade_count integer DEFAULT 0,
  max_drawdown numeric(15,2) DEFAULT 0,
  circuit_breaker_hit boolean DEFAULT false,
  created_at timestamptz DEFAULT now(),
  UNIQUE(user_id, trade_date)
);

-- 3. Affiliate audit tag
ALTER TABLE public.trade_log 
ADD COLUMN IF NOT EXISTS eligible_for_rebate boolean DEFAULT true;
